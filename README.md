# Русификатор для macOS

Нативная утилита строки меню, которая превращает голосовую расшифровку в
аккуратный русский текст через OpenAI-совместимый API. Каждый запуск обработки
изолирован: в запрос входят только фиксированный системный промпт и текст,
который находится в поле прямо сейчас. Последние пять успешных обработок
хранятся локально на Mac, но никогда не добавляются в следующие запросы.

Текущая версия — `1.0` (каноническая `1.0.0`). Одновременно работает только один
экземпляр: повторный запуск выводит вперёд уже открытое окно и завершается.
Если окно было закрыто минуту и дольше, при следующем открытии редактор чистый —
история при этом не трогается, а начатая обработка спокойно дописывается.

По умолчанию приложение использует:

- адрес `https://liteapi.gotacat.dev/`;
- модель `proxy/gpt-5.6-terra`;
- маршрут `POST /v1/chat/completions`.

## Требования

- macOS 26;
- Xcode 26 со Swift 6.2 или новее.

## Сборка и тесты

```sh
swift build
swift test
scripts/test-system-prompt.sh
```

## Установка

Обычный путь для тех, кому приложение просто передали: скачать
`Rusifikator-<версия>.dmg` со страницы релизов, открыть образ и перетащить
«Русификатор» в «Программы».

Сборка подписана только локальной ad-hoc подписью, поэтому при первом запуске
macOS откажется открывать её и предложит разобраться в системных настройках.
Это ожидаемо и делается один раз:

1. попробовать открыть приложение из «Программ»;
2. открыть «Системные настройки → Конфиденциальность и безопасность»;
3. в разделе «Безопасность» нажать «Открыть всё равно» и подтвердить паролем.

После этого приложение запускается двойным щелчком, как любое другое.
Подробности об ограничении — в разделе «Подпись, Gatekeeper и Developer ID».

Сборка из исходников:

```sh
scripts/package-app.sh
scripts/smoke-test-app.sh dist/Rusifikator.app
cp -R dist/Rusifikator.app /Applications/
open /Applications/Rusifikator.app
```

После запуска значок появится в строке меню; в Dock приложение не показывается.
Левый клик по значку открывает редактор, правый — меню с версией, настройками и
выходом. В настройках нужно ввести API-ключ и нажать «Сохранить». Ключ нельзя
передавать в чат, добавлять в исходный код или вводить в команды терминала.

## Обновление

В настройках есть действие «Проверить обновления». Рядом с ним видно текущее
состояние: идёт проверка, установлена последняя версия, доступна новая версия
или проверка не удалась. Кроме того, приложение раз в сутки тихо проверяет
канал само и не перебивает работу — окно обновления открывается только по
явному нажатию.

Обновления устроены на Sparkle — стандартном для macOS механизме обновления
приложений вне App Store:

- метаданные и артефакт скачиваются только по HTTPS;
- образ проверяется подписью EdDSA перед распаковкой; неподписанный или
  изменённый файл не устанавливается;
- установку подтверждает владелец Mac, после чего приложение перезапускается.

Канал обновлений — файл `appcast.xml`, приложенный к последнему релизу на
GitHub. Адрес зашит в приложение и не меняется:
`https://github.com/xonika9/rusifikator-macos/releases/latest/download/appcast.xml`.

Приложение нельзя обновить, пока оно запущено из смонтированного образа диска
или из карантинной копии: сначала нужно перенести его в «Программы». В этом
случае приложение прямо об этом и говорит.

## Подпись, Gatekeeper и Developer ID

У проекта нет сертификата Apple Developer ID и нотарного заверения. Что из
этого следует:

- **Первый запуск.** Скачанный образ помечается карантином, и Gatekeeper
  блокирует ad-hoc подписанное приложение. Разблокировка делается вручную через
  «Системные настройки», как описано выше.
- **Обновления.** Sparkle снимает карантин с проверенного обновления, поэтому
  повторять разблокировку после каждого обновления не нужно — только при первой
  установке.
- **Что заменяет Developer ID.** Подлинность обновлений держится на подписи
  EdDSA: приложение доверяет только тем файлам, которые подписаны закрытым
  ключом владельца.
- **Чего это не даёт.** Ad-hoc подпись не подтверждает разработчика перед
  macOS и не проходит нотарное заверение. Никакие защиты macOS при этом не
  отключаются: Gatekeeper, карантин и проверка подписей работают штатно.
- **Ограничение ключей.** Пока приложение не подписано Developer ID, сменить
  ключ EdDSA через обновление нельзя. Потеря закрытого ключа означает, что
  установленные копии придётся переустанавливать вручную.
- **Архитектура.** Сборка собирается под текущую машину (Apple Silicon) и в
  метаданных обновления помечена как `arm64`. Mac на Intel такое обновление не
  получит.

### Если появится Developer ID

Понадобятся три изменения, и ни одно из них не ломает уже установленные копии:

1. в `scripts/package-app.sh` заменить `--sign -` на подпись сертификатом
   «Developer ID Application» с `--options runtime`;
2. добавить в релизный процесс нотарное заверение (`notarytool`) и `stapler`
   для готового `.dmg`;
3. оставить подпись EdDSA как есть — Sparkle проверяет обе, а менять ключ и
   сертификат одновременно нельзя.

После этого раздел про ручную разблокировку из README можно убрать.

### Ключ подписи обновлений

Закрытый ключ EdDSA лежит в Keychain текущего пользователя (запись `ed25519`,
создана `generate_keys` из Sparkle). Его нет и не должно быть в репозитории,
логах, артефактах и готовом приложении. В приложение попадает только открытая
часть — `SUPublicEDKey` в `Info.plist`.

Резервная копия делается вручную и хранится вне репозитория:

```sh
.build/artifacts/sparkle/Sparkle/bin/generate_keys -x ~/Desktop/rusifikator-eddsa.key
```

Файл после переноса в надёжное место нужно удалить. Публичную часть можно
получить в любой момент:

```sh
.build/artifacts/sparkle/Sparkle/bin/generate_keys -p
```

## Подготовка следующей версии

Релизами занимается репозиторный навык `release` (см. `.claude/skills/release`).
Он согласовывает версию, обновляет `CHANGELOG.md`, прогоняет проверки, собирает
артефакты и доводит публикацию до проверяемого обновления. Отдельные шаги можно
запустить и вручную:

```sh
scripts/release-checks.sh            # весь обязательный набор проверок
scripts/build-release-artifacts.sh   # dmg, appcast.xml, контрольные суммы
scripts/verify-release-artifacts.sh  # проверка готовых артефактов
```

Дымовой тест запускает упакованную копию, поэтому перед ним нужно закрыть
установленный «Русификатор»: одновременно работает только один экземпляр, и
запущенная копия не даст тестовой стартовать. Скрипт прямо называет
мешающий процесс.

При сборке метаданных обновления macOS спрашивает разрешение на доступ к
закрытому ключу в Keychain. Скрипт молча ждёт ответа, поэтому в первый раз в
диалоге нужно выбрать «Всегда разрешать» — иначе он будет появляться каждый раз.

Порядок подготовки версии:

1. записать изменения в раздел `Unreleased` файла `CHANGELOG.md`;
2. согласовать номер версии по SemVer;
3. проставить его в `CFBundleShortVersionString` (пользовательский вид, `1.1`)
   и `CFBundleVersion` (канонический, `1.1.0`) в
   `Sources/Rusifikator/Resources/Rusifikator-Info.plist`;
4. перенести `Unreleased` в раздел версии с датой;
5. запустить `scripts/release-checks.sh`;
6. опубликовать релиз с тегом `v<каноническая версия>`, приложив `.dmg`,
   `appcast.xml` и `SHA256SUMS`.

`CFBundleVersion` должен строго расти от релиза к релизу: именно его сравнивает
канал обновлений.

### Если релиз не удался

Опубликованную версию не переписывают и не двигают: тег и релиз остаются как
есть. Исправление выходит следующей версией.

- **Сломались артефакты, релиз ещё не опубликован.** Удалить `dist/release`,
  исправить причину, прогнать `scripts/release-checks.sh` заново.
- **Релиз опубликован, а приложение непригодно.** Выпустить следующую патч-
  версию обычным порядком. Её `appcast.xml` сразу становится актуальным, потому
  что канал всегда указывает на последний релиз.
- **Релиз опубликован без `appcast.xml`.** Канал обновлений сломан для всех
  установленных копий. Нужно приложить недостающий файл к тому же релизу — это
  единственный случай, когда существующий релиз дополняют, и он не меняет уже
  опубликованный образ.
- **Ключ подписи утерян.** Обновления восстановить нельзя: понадобится новая
  версия с новым `SUPublicEDKey`, которую все ставят вручную.

## Настройка и приватность

- Адрес и модель хранятся в `UserDefaults`.
- API-ключ хранится только в macOS Keychain и привязывается к защищённому
  HTTPS-origin. При смене провайдера ключ нужно ввести заново.
- Последние пять пар «исходник — результат» записываются в локальный JSON-файл
  внутри `Application Support`. Историю можно целиком удалить из приложения;
  в аналитику, журналы и новые запросы она не передаётся.
- Очистка поля отменяет текущий запрос и удаляет исходник, результат и ошибку,
  но не затрагивает историю.
- Если окно было скрыто не меньше минуты, при следующем открытии редактор
  очищается сам: пропадают исходник, результат, ошибка и отметка о копировании.
  История остаётся. Выполняющийся запрос ради очистки не прерывается — он
  дописывается, попадает в историю, а очистка происходит при следующем открытии.
  Отсчёт ведётся по календарному времени, поэтому сон Mac засчитывается.
- Проверка обновлений обращается только к каналу обновлений и не передаёт туда
  ни текст, ни настройки, ни API-ключ.
- Копирование выполняется только по явному нажатию. После этого текст находится
  в системном буфере обмена и может быть доступен его менеджерам, Universal
  Clipboard и другим приложениям.
- Сам провайдер получает текущую расшифровку. Его хранение и обработка данных
  находятся вне контроля приложения и должны оцениваться отдельно.

Проверка соединения использует черновые значения из окна настроек и короткий
служебный текст. Она не сохраняет настройки автоматически.

Автозапуск через `SMAppService` доступен для копии, установленной в
`/Applications`. После включения macOS может потребовать подтверждение в
системных настройках.

## Разработка в Xcode

Открой `Package.swift` через `File → Open` в Xcode. Для обычной разработки
достаточно `swift build` и `swift test`; готовый пакет создаётся отдельным
скриптом, потому что проект намеренно остаётся компактным Swift Package.

## Значки

В строке меню временно используется системный SF Symbol
`character.cursor.ibeam`; у пакета приложения пока стандартный значок macOS.
Это временные заменяемые элементы.

Для финальной версии понадобятся два разных исходника:

- значок приложения — квадратный PNG 1024×1024 без предварительно скруглённых
  углов; из него создаётся `.icns` или набор AppIcon;
- значок строки меню — монохромный шаблон с прозрачным фоном, желательно
  векторный PDF или SVG, рассчитанный на размер около 18×18 pt.

## Что ещё требует проверки владельцем

- успешный живой запрос с настоящим API-ключом и выбранной моделью;
- качество результата на нескольких реальных расшифровках;
- запуск при входе после перезагрузки установленной копии;
- перенос и запуск пакета на втором Mac, включая разблокировку в системных
  настройках;
- установку обновления с версии `1.0` на следующую после первой публикации;
- правила хранения расшифровок на стороне API-провайдера.
